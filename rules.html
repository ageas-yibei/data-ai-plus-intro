How each file is sorted每份文件怎么分拣

Every file in a submission gets one of six answers. The files answered CORE go on to the Facts Agent, which extracts the data, unless a person in the review app rules otherwise: a file marked Keep goes on whatever its answer, and a file marked Drop does not. The steps are checked in order, and the first one that matches decides. If none matches, a person decides. No file is ever deleted. 提交里的每份文件都会得到六种结论之一。结论为 CORE 的文件交给数据提取智能体（Facts Agent）提取数据。复核工具里有人标了 Keep 或 Drop 的，以人为准：标 Keep 的，不论结论都交过去；标 Drop 的不交。规则按顺序逐步检查，第一步命中就定结论；一步都没命中，交给人判断。任何文件都不删除。

At a glance一览

Steps 0 to 7 are checked in order, and the first that matches gives the answer. If none matches, the rows marked — are checked in order; those answered UNDECIDED leave the file to a person with the reason recorded, and the last records none. The two rows marked + run afterwards, over every answer.第 0 到 7 步按顺序检查，第一步命中就定结论。一步都没命中，再按顺序查标 — 的几行：结论为 UNDECIDED 的交给人判断并记下原因，最后一行不记原因。标 + 的两行，在所有结论定完之后再过一遍。

COREPart of the submission, and the answer passed on to the Facts Agent. What the rules read规则读什么

Most decisions rest on the file name, and so do most mistakes.多数判断靠文件名，多数错判也出在文件名上。

Folder文件夹

Which folder of the export the file is in: a submission folder, a notes folder, an approvals folder.文件在导出目录的哪个文件夹里：提交材料、备注、审批。

Limit:局限： a file saved in the wrong folder can get the wrong answer. The folder alone makes a file CORE only in the two submission folders, and the reason then says so: core_in_submission_folder.文件放错了文件夹，就可能判错。单凭文件夹定 CORE，只限两个提交文件夹，理由会写明 core_in_submission_folder。

File name文件名

Most rules read only this. The ID prefix the export adds is removed first, and a name the export split at a “/” is joined back. Step 2 reads the name as it is on disk instead: the ID stays, and of a split name only the part after the “/” is read. Step 6's test of who sent a file also reads the name on disk, when it looks for the words that mark a cedant's document (slip, narrative, wording and the like) and for the internal words listed under Content.多数规则只读文件名。先去掉导出系统加的编号前缀；名字含“/”、被导出系统拆成两级的，先拼回原名。第 2 步不这样做，读的是磁盘上的原样文件名：编号前缀保留，拆成两级的只读“/”后面那一段。第 6 步判断谁送来的，找 slip、narrative、wording 这类表明是分出公司文件的词，以及“内容”里列的内部用语时，也读磁盘上的原样文件名。

Limit:局限： if the name says nothing, or says the wrong thing, the answer can be wrong. Every known miss began with the name.文件名什么都没说或说错了，就可能判错。已知漏判都是从文件名开始的。

Format格式

The extension. Never misread.扩展名。不会看错。

Limit:局限： the extension does not say what is inside. A PDF can be a slip, a printed email or a photo.扩展名说明不了文件里是什么。同为 PDF，可能是条款单、打印的邮件，也可能只是一张照片。

Content内容

The text the machine extracted. Some tests read only the start: the withdrawal words in the first 500 characters, the email headers and step 5's internal words in the first 800; the title that gives the type in the first 500, or a workbook's sheet names. An email is read in its subject and its newest message, or all of it for a forward or a whole thread. Of a .msg or .eml the rules get only the first 660 characters of the body, and read no further. The market reference and the cedant's list of what it sent are searched in the whole text. Step 6's test of who sent a file looks for internal, UW note, underwriter's note, 审批, 承保指引, 分入, 内部, 签核, 呈核, 批核 or 签呈 (traditional characters too) in the whole text of a PDF and the first 20,000 characters of any other file: where neither the folder nor the name says the file is the cedant's, one found means step 6 keeps nothing.机器读出的文字。有几项只看开头：作废用语看前 500 个字符，邮件头和第 5 步的内部用语看前 800 个；定类型的标题看前 500 个字符，或工作簿的工作表名。邮件看主题和最新一封；转发或整串打印的邮件看全文。.msg、.eml 的正文，规则只拿到前 660 个字符，再往后都读不到。市场编号和分出公司的送件列表，全文都找。第 6 步判断谁送来的，要找 internal、UW note、underwriter's note、审批、承保指引、分入、内部、签核、呈核、批核、签呈（繁体同样算）：PDF 找全文，其他文件找前 20,000 个字符。文件夹和文件名都没表明是分出公司的，找到一个，第 6 步就不留。

Limit:局限： a scan has no text for the rules to read. Nor does a PDF whose text layer the machine judged unusable: only step 4 still reads that layer, where the name says the PDF is an email, for a line with its share, FOT, firm order or proposed structure. The vision model's transcription of a scan goes with the file to the Facts Agent and to the second read, and, with a store, to the review app. No rule reads it, and it changes no answer. A scan with a page's words transcribed, not only a logo's or a stamp's, counts as read: it is not flagged for a person to read, and the RAG Gate does not count it unread.扫描件没有文字可读。机器判定文字层不可用的 PDF，也算没有文字：只有第 4 步还读这层文字，限文件名表明是邮件的，看有没有写明带比例的份额，或 FOT、firm order、proposed structure。视觉模型转写的扫描件文字，随文件交给数据提取智能体，也给二次阅读；配置了文件库时，复核工具里也看得到。规则不读转写，转写也不改结论。扫描件转写出了页面文字（只有标志或印章上的字不算），就算已读：不再标出要人看，RAG 闸门也不算未读。

The underwriter's type核保类型

Every file also gets a type, written beside its answer in <TNO>_inventory.csv in five columns. The columns are for people; no rule reads them. Five tests work out the same type for themselves, from the file's own words; none of them takes the folder step or the format step below. Step 6 reads it twice, to tell who sent a file and to keep a contract or submission document: the name, then the title at the top of the text or a workbook's sheet names. R18_kyc_licence and R7_notes_folder_named read the name alone. R17_post_binding_report reads the name, then the title or the sheet names, and has its own folder test, in the last step above.每份文件还会得到一个类型，在 <TNO>_inventory.csv 里写在结论旁边，共五栏。这五栏给人看，规则不读。有五处判断自己定同样的类型，只看文件本身的字，不用下文按文件夹、按格式定类型的那两步。第 6 步用到两次，判断谁送来的、留不留合约或提交材料：先看文件名，再看正文开头的标题或工作簿的工作表名。R18_kyc_licence 和 R7_notes_folder_named 只看文件名。R17_post_binding_report 先看文件名，再看标题或工作表名；另外按自己的一套名字查文件夹，见上文最后一步。

How the type is worked out类型怎么定

First the name. If the name says nothing or too little, the text: the title at the top of the document, or a workbook's sheet names. Then the folder: in Slip & End't a workbook is premium and statistics and any other file a slip; U W Information means submission. Then the format: a workbook nothing else typed is premium and statistics. Last, S+R, signed, countersigned, signiert or executed in the name makes a signing page. An email is typed by its file name, never its body.先看文件名。文件名没说或说得不够，再看正文：文件开头的标题，或工作簿的工作表名。再看文件夹：Slip & End't 里的工作簿算保费与统计，其他文件算条款单；U W Information 里的算提交材料。再看格式：别处都定不了的工作簿，算保费与统计。最后，文件名写着 S+R、signed、countersigned、signiert 或 executed 的，算签署页。邮件只看文件名，不看正文。

The folder also says whose and when. A notes folder makes a file ours, as the Ours row says. A file in Loss information, Results, QS Reporting, Treaty Update, Special Acceptances or PNOC came after binding: losses become a loss update, premium or exposure figures the results, a special acceptance a special-acceptance request, anything else what the folder says. In a notes folder, in these folders and in Reciprocal Business, an email, a Q&A, a line confirmation, a comparison, an archive, an image and a system file keep their own type, and so does a file that sits, or has an exact copy, in Slip & End't or U W Information.文件夹还说明是谁的、什么时候来的。备注文件夹里的文件算我方的，见“我方”一行。Loss information、Results、QS Reporting、Treaty Update、Special Acceptances、PNOC 里的文件是成交之后来的：赔付算赔案更新，保费或风险敞口算经营结果，特别承保算特别承保申请，其余按文件夹定。邮件、问答、份额确认、对比、压缩包、图片、系统自动生成的文件，放在备注文件夹、这些文件夹或 Reciprocal Business 里，仍按自己的类型；本身在、或有完全相同的副本在 Slip & End't、U W Information 里的文件，也一样。

What these rules do not decide这些规则不管的事

These rules decide what each file is. Whether the whole submission can go on without a person checking it is decided afterwards, by the RAG Gate.这些规则只判断每份文件是什么。整份提交能不能不经人看就往下送，之后由 RAG 闸门判断。

Nothing after the rules changes an answer. The RAG Gate reads the answers and changes none. Nor does the second read, where one is run: a file the rules did not keep that it reads as a submission document goes on the RAG Gate's G11 list, and its other verdicts change nothing.规则之后的环节都不改结论。RAG 闸门只读结论，一条不改。二次阅读若跑过，也不改结论：规则没留下、二次阅读认作提交文件的，列进 RAG 闸门的 G11 名单；其余答复什么都不改。

A wrong answer stays in <TNO>_inventory.csv as the rules wrote it. Where a person answers a file otherwise, the review app shows a disagreement. Once the person's Keep or Drop stands, it changes what goes on to the Facts Agent, never the answer. The known number of misses is a minimum, not a measurement: the people who checked the answers started from the machine's output.错判原样留在 <TNO>_inventory.csv 里，不改写。人的答复与机器不同时，复核工具里显示为“分歧”。人标的 Keep 或 Drop 定下来后，改的是交给数据提取智能体的文件，不改结论。已知漏判数只是下限，不是实测：人工核对本身就是从机器的结果出发的。
