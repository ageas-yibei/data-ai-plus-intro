Internal LLM API reference

Developer cheat sheet for the two in-house OpenAI-compatible hosts. Both sit on the company intranet (10.253.x.x), so you must be on the internal network or VPN. Traffic is HTTP, not HTTPS.

本页为开发者速查表，仅维护英文版本。

!
Keys are not published on this page

Everywhere a key belongs you will find see the internal note. The values live in 04. docs\LLM-API-REFERENCE.md on the project share, and in each stage's own gitignored config (triage/llm_config.json).

These hosts are private company addresses. Keep the endpoints inside TPRe, and never point a cloud provider at a production submission.

The protocol both hosts speak

Every endpoint speaks the OpenAI Chat Completions protocol.

GET  {base_url}/models
POST {base_url}/chat/completions

Header on every call

Authorization: Bearer <api_key>
Content-Type: application/json

Reasoning switch (this host)

A Qwen chat-template switch, not reasoning_effort:

{
  "chat_template_kwargs": { "enable_thinking": false }
}

Sending reasoning_effort here is silently ignored — the server thinks anyway.

Minimal Python

from openai import OpenAI

client = OpenAI(
    base_url="http://10.253.17.70:9090/v1",
    api_key=COMPANY_API_KEY,        # see the internal note
)

# Text
resp = client.chat.completions.create(
    model="mlx-community/Qwen3.8-27B-8bit",
    messages=[{"role": "user", "content": "Say hello in one sentence."}],
    extra_body={"chat_template_kwargs": {"enable_thinking": False}},
)
print(resp.choices[0].message.content)

# Vision / OCR — send a page image
resp = client.chat.completions.create(
    model="mlx-community/olmOCR-7B-0725-8bit",
    messages=[{
        "role": "user",
        "content": [
            {"type": "text", "text": "Transcribe this document page."},
            {"type": "image_url", "image_url": {"url": "data:image/png;base64,<...>" }},
        ],
    }],
)
print(resp.choices[0].message.content)

Curl

curl -s http://10.253.17.70:9090/v1/models \
  -H "Authorization: Bearer $COMPANY_API_KEY"

curl -s http://10.253.17.70:9090/v1/chat/completions \
  -H "Authorization: Bearer $COMPANY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "mlx-community/Qwen3.8-27B-8bit",
    "messages": [{"role": "user", "content": "ping"}],
    "chat_template_kwargs": {"enable_thinking": false}
  }'

2. TKO data centre — OpenCode

Two separate OpenAI-compatible gateways on the same host. Each has its own port, key and model. They are not interchangeable: a request to :4000 with the Gemma key (or the other way around) will fail.

2a. Qwen3.8-27B — port 4000

FieldValue
Base URLhttp://10.253.16.94:4000/v1
API keysee the internal note
Model idqwen3.8-27b
Display nameQwen3.8-27B
Default temperature0.7
Default reasoningmedium

This gateway does not serve a vision model. A vision request returns HTTP 404. Keep OCR on Mac Studio :9090 (or use Gemma on :4001).

Reasoning is a dial, not an on/off switch. Send reasoning_effort:

LevelSent asTypical use
low"low"Long batch jobs. Fastest.
medium"medium"Server default.
high"xhigh"Highest effort. The gateway's own word is xhigh, not high.

Leaving the field out returns to the server default (medium). On this gateway that was measured at ~16 s for a short ping — over thousands of files that is hours of extra wall-clock. For batch work, set "low" explicitly.

from openai import OpenAI

client = OpenAI(
    base_url="http://10.253.16.94:4000/v1",
    api_key=QWEN_KEY,               # see the internal note
)

resp = client.chat.completions.create(
    model="qwen3.8-27b",
    messages=[{"role": "user", "content": "Summarise this slip in three bullets."}],
    temperature=0.7,
    extra_body={"reasoning_effort": "low"},
)
print(resp.choices[0].message.content)
curl -s http://10.253.16.94:4000/v1/models \
  -H "Authorization: Bearer $QWEN_KEY"

curl -s http://10.253.16.94:4000/v1/chat/completions \
  -H "Authorization: Bearer $QWEN_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3.8-27b",
    "messages": [{"role": "user", "content": "ping"}],
    "reasoning_effort": "low"
  }'

Stdlib-only call (no openai package)

How this project actually calls the endpoint: a locked workstation cannot pip install, so the pipeline speaks the protocol with urllib, reading the host and key out of its own gitignored config.

import json, urllib.request

BASE = "http://10.253.16.94:4000/v1"
KEY = cfg["api_key"]                # triage/llm_config.json, gitignored

req = urllib.request.Request(
    BASE + "/chat/completions",
    data=json.dumps({
        "model": "qwen3.8-27b",
        "messages": [{"role": "user", "content": "ping"}],
        "reasoning_effort": "low",
    }).encode(),
    headers={
        "Authorization": f"Bearer {KEY}",
        "Content-Type": "application/json",
    },
    method="POST",
)
with urllib.request.urlopen(req, timeout=120) as resp:
    body = json.loads(resp.read().decode())
print(body["choices"][0]["message"]["content"])

Gotchas

  • Exact model ids. On Mac Studio use the full org/name slug from the table. On TKO use the short ids (qwen3.8-27b, gemma-4-26B-A4B). GET /v1/models is the source of truth for what is loaded.
  • The wrong reasoning field is silent. Mac Studio wants chat_template_kwargs.enable_thinking. TKO :4000 wants reasoning_effort. The other field is ignored and the server thinks at its default.
  • TKO keys are per port. The :4000 key does not work on :4001, and the other way around.
  • Mac Studio loads one model at a time. A 404 or an unexpected reply usually means a different model is loaded than the one you named.
  • Timeouts. Hybrid models with reasoning on can take minutes. 120 s is often too short; 600 s is a safer ceiling.
  • Confidentiality. These hosts are private company addresses. Do not point cloud providers at production submissions.
