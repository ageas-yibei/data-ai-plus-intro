The lifecycle of
one submission.

Each treaty renewal arrives as a submission pack: a slip, schedules, spreadsheets, emails, a deck. Today its numbers are keyed in by hand, two months after the decision. This is how AI Data+ turns that pack into structured data before the decision.

Scroll to view the lifecycle of one submission

One submission pack,
many formats.

A submission arrives as a slip, schedules, spreadsheets, emails and a deck. The figures the underwriter needs are spread across all of them, with no common structure.

One pack, five formats, no structure

Find the core files.

The Submission Agent reads every file and picks out the ones that actually carry the data: the slip, the EPI schedule, the loss history, the wording. The rest stay with the treaty as supporting material.

Module A — Submission Agent
Red / amber / green gate: only green passes to the next step. During development a Validation Flywheel reviews every call and feeds the corrections back into the agent.

Extract the facts.

The Facts Agent reads the core files against the agreed Shopping List and fills one structured TreatyRecord per treaty. Every figure is located in a document, never invented. A recipe per cedant tells it where to look, and sharpens with each treaty reviewed.

Module B — Facts Agent
Red / amber / green gate: only green records pass to the next step. During development a Validation Flywheel reviews every record and feeds the corrections back into the agent.

Structured data,
ready to use.

From the TreatyRecord the Template Agent produces what the underwriter needs: an Analysis Report to compare and decide on, and an Entry Report that goes straight into TPR, with nothing re-keyed.

Module C — Template Agent

Data before the decision.

The underwriter opens a structured, comparable view of the treaty at the start of underwriting. TPR is filled by RPA or API at the end — instead of two months of keying after the decision.
