When a person has to look什么时候需要人看

Can this submission be passed on to downstream? After the machine sorts a treaty’s files, the gate asks that one question about the result — and the three colours are the three answers. Green: it can. Amber: a double check is needed first. Red: the result is not trusted, so find out why. 这份提交能不能往下送给下游？机器分拣完一份合约的文件后，闸门就对这个结果只问这一个问题，三种颜色就是三个答案：绿灯，可以往下送；黄灯，要先复核；红灯，不信任这次结果，先查清原因。

Green绿灯

It can be passed on. Downstream gets it with nobody looking first.可以往下送。下游直接拿到，事先不必有人看。

Minus a standing audit sample: about one treaty in five is read anyway, so the gate keeps being measured after it stops being reviewed.但保留固定抽查：约每五份抽一份照样有人读，好让闸门在没人复核之后仍被持续检验。

Amber黄灯

Double check needed. Somebody looks before it goes on.需要复核。先有人过目，再往下送。

Most amber rules name the files to look at, and that list is the work — not the whole treaty. Two of them name no file: they are facts about the treaty itself.多数黄灯规则会列出要看的文件，要做的就是这份名单，而不是整份合约；其中两条不列文件，说的是这份合约本身的情况。

Red红灯

Investigation needed. The result is not trusted — find out why before anything goes on.需要查清。不信任这次结果——先弄明白原因，再谈往下送。

The amber list still comes with it, so the person knows where to start.黄灯名单一并附上，好让人知道从哪里入手。

How the colour is picked颜色怎么定

  1. If any stop-the-pack test failed → red.凡“整份材料包停下”的测试有一条未过 → 红灯。
  2. Otherwise, if any look-at-these test failed → amber.否则，“复查这些文件”的测试有一条未过 → 黄灯。
  3. Otherwise → green. Nothing fired, and having no reason to stop is what “it can be passed on” means.否则 → 绿灯。没有任何一条触发；没有要停下的理由，就是“可以往下送”的意思。

Keeping an extra file does not change the colour at all: the file is still in the pack, and someone can read it. Throwing one away on a weak reason turns the light amber, because nobody will see it unless we say so. 多留一份文件根本不影响颜色：它还在材料包里，总有人读得到。凭弱理由扔掉才会亮黄灯——不点出来，就没人看得见。

Stop the pack整份材料包停下

These four mean the result is not trusted: find out why before anything is passed on. Click a row for the technical name.这四条一旦触发，即不信任这次结果：往下送之前，先查清原因。点开一行可看技术名称。

Look at these files复查这些文件

The pack is not stopped — but somebody looks before it goes on. Most of these rules name the files to work through; two of them name no file, because what needs the second look is the treaty itself.材料包不必停下，但要先有人过目，再往下送。多数规则会列出要看的文件；其中两条不列文件，因为要复核的是这份合约本身。

It threw a file away on a weak reason凭弱理由扔掉了文件
A file in a submission folder was dropped, and the filename itself does not carry the reason. Check it before it leaves.提交文件夹里的文件遭丢弃，而文件名本身撑不起这个理由。文件离场前得看一眼。

G5_contested_discard
Which discards哪些丢弃要看
Only unique files in a recognised submission folder. Always contested: version-pair / UW-derivative name shapes. Contested unless the name itself fired: internal-signal, withdrawn-marker (body-only hits). Envelope mail and the containers it came in, picture files, comparison tags, newsletters, OS junk, notes-folder and broker variants are never contested.仅限已识别的提交文件夹内的唯一文件。一律要看：版本对、核保衍生件这两类文件名形态。内部信号、撤回标记两条，仅命中正文时要看，文件名本身命中则不看。信封邮件及其所在的压缩包、图片文件、对比标记、通讯、系统垃圾、notes 文件夹及经纪人变体，一律不看。
Unknown reason未知理由
A discard citing a reason the gate has never seen halts the build. It does not fail open.丢弃理由若是关卡从未见过的，构建直接停止，绝不悄悄放过。
A review clears it复核可消除
No. A submission somebody went through end to end still comes out amber if it holds one contested discard. This is the rule the whole gate rests on — every real miss found so far had this shape — and a review is not evidence about it.不可。即便整份提交有人从头看到尾，只要还有一份存疑的丢弃，仍是黄灯。这条规则是整个闸门的立足点——目前发现的真漏掉，每一例都是这个形状——复核并不能替它作证。
It never decided on some files有些文件没有下判断
Those files sit as “undecided”. A person has to place them.这些文件停在“未定”，要人来归位。

When somebody has already looked已经有人看过之后

A person’s reading reaches the gate. It is recorded file by file, and the colour is worked out again with it.人看过的结果会送到闸门：逐份文件记录下来，再据此重新算一遍颜色。

What a review changes复核会改变什么

  1. It clears the two rules about files nobody placed — the machine sat on the fence and it never decided on some files. A reviewer places them, so the reason is gone.它只消除两条与“没人归位的文件”有关的规则：大半文件没有表态、有些文件没有下判断。复核的人把这些文件归了位，理由自然不在了。
  2. It clears nothing else. A submission somebody went through end to end is still amber if one file was thrown away on a weak reason, if a file carries another treaty’s market reference, if the folders are unfamiliar, or if everything kept rests on inference.其余一概不消除。即便整份提交有人从头看到尾，只要有一份文件是凭弱理由扔掉的、或哪份文件带着另一份合约的市场编号、或文件夹不是认得的那一套、或留下的核心全凭推断，仍是黄灯。
  3. Nothing recorded, nothing changed. A submission nobody has reviewed comes out exactly as it did before anyone could — which is why green is still reachable in production, where there is no review step at all.没有记录，就什么都不变。没人复核过的提交，判定结果与从前完全一致——所以在根本没有复核环节的生产流程里，绿灯照样拿得到。

So a person looking can only ever make a verdict better, and a green never depends on one. 因此，有人看过只可能让判定变好，而绿灯从不以它为前提。

What counts as a review什么才算复核

  1. An answer on each file, from a named person. Marking a row as one you could not settle is not settling it — that is how somebody says so.对每份文件都有答复，且署名到人。把一行标为“定不了”并不算定下来——那正是在说这件事。
  2. A review done before the review app existed counts too, on the authority of a register that names who went through which submission, and when.在复核工具出现之前做过的复核同样算数，依据是一份登记表：谁看过哪份提交、什么时候看的。
  3. The work having been compared is never read as somebody signing it off. A file landing in a folder must not turn a submission green; a person’s name has to be in the register.光有一份比对结果，绝不等于有人签核过。一份文件落进某个文件夹，不能就此把提交变成绿灯；人的名字得落在登记表上。

If the treaty is sorted again and its documents move, the review no longer covers them: the build stops rather than grade on stale answers. A rule change that only relabels a file does not stale it — the person read the document, not the label. 若合约重新分拣、文件本身发生变动，原先的复核就覆盖不到它们：构建会停下，而不是拿过时的答复去判定。仅仅是规则改动、只换了标签，则不算过时——人读的是文件本身，不是机器贴的标签。

This is the file-sort gate这是文件分拣这一关

Facts extraction uses the same three colours later: green auto-accepts, amber checks flagged fields, red reviews the whole record, and retrospective cases are also checked against TPR booked values. That is a separate process, not this gate.后续的信息提取环节同样用红黄绿三色：绿灯自动通过，黄灯核对标出的字段，红灯复核整单；回溯案例还要与 TPR 入账值比对。那是另一关，不是这一关。
