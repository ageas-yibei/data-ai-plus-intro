Data & AI Engineer数据与 AI 工程师Submission Agent
The Data & AI Engineer triggers the Submission Agent. A deterministic rule picks the Core files; the LLM only classifies what the rule can't. Every file is kept, tagged Core or Others. Signed off at step 3.数据与 AI 工程师触发 Submission Agent。确定性规则先选出核心文件，规则未命中的才交给 LLM 分类。所有文件都保留，标记为核心或其他。在第 3 步签核。

Data extraction数据提取

Data & AI Engineer数据与 AI 工程师Facts Agent
The Data & AI Engineer triggers the Facts Agent. It reads the validated Core files into one TreatyRecord: every field on the signed Shopping List, with where each value was found. Locates, never invents. If no recipe fits this treaty, the Business Analyst writes one (with a coding agent) and the run repeats. Signed off at step 5.数据与 AI 工程师触发 Facts Agent。它将已确认的核心文件读取为一条 TreatyRecord：按已签核的 Shopping List 逐字段提取并记录出处。只定位，不臆造。若没有适用的 recipe，由业务分析师（借助编码 agent）编写后重跑。在第 5 步签核。

Result validation结果验证

Reviewer复核人→Domain Specialist领域专家
Validation Flywheel, Module B. The vendor reviewer checks the record field by field; the Domain Specialist signs it off and rules on any field that differs from what TPR booked. Answer key = TPR booked values, retrospective cases only. Corrections go back to the Data & AI Engineer.验证飞轮，模块 B。外包复核人逐字段检查记录；领域专家签核，并裁定与 TPR 入账值不一致的字段。标准答案 = TPR 入账值，仅回溯案例。纠正结果反馈给数据与 AI 工程师。

Report generation报告生成

Data & AI Engineer数据与 AI 工程师Template Agent
The Data & AI Engineer triggers the Template Agent. From the one validated record it fills the Analysis Report (for the underwriter) and the Entry Report (for TPR). No sign-off: the numbers were signed off at step 5.数据与 AI 工程师触发 Template Agent。用同一条已确认的记录填出分析报告（给核保人）和录入报告（给 TPR）。无需签核：数据已在第 5 步签核。
